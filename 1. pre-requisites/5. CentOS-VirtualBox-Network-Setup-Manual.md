# CentOS VirtualBox Network Setup Manual

This guide configures CentOS and Ubuntu virtual machines with two network adapters:

- **NAT adapter** for reliable internet access.
- **Bridged adapter** so Windows and CentOS can communicate as separate machines on the same local network.

## 1. Understand the final setup

For the setup used in this guide:

| Device or interface | IP address | Purpose |
|---|---:|---|
| Home router | `192.168.1.1` | Local-network gateway and DNS |
| Windows computer | `192.168.1.9` | Physical host machine |
| CentOS `enp0s3` | `10.0.2.15` | VirtualBox NAT/internet |
| CentOS `enp0s8` | `192.168.1.200` | Bridged/local-network access |
| Ubuntu `enp0s3` | `10.0.2.15` | VirtualBox NAT/internet |
| Ubuntu `enp0s8` | `192.168.1.201` | Bridged/local-network access |

> The addresses above are examples from this working setup. On another network, first check the Windows address, subnet mask, and gateway with `ipconfig`.

The resulting design is:

```text
Internet
   |
Home router (192.168.1.1)
   |
Wi-Fi network (192.168.1.0/24)
   |-- Windows computer (192.168.1.9)
   |-- CentOS VM bridged interface (192.168.1.200)
   |-- Ubuntu VM bridged interface (192.168.1.201)

VirtualBox NAT
   |-- CentOS VM NAT interface (10.0.2.15)
```

In Bridged mode, the CentOS VM behaves like another physical computer connected to the router.

## 2. Shut down the virtual machine

Completely shut down the CentOS VM before changing its VirtualBox network settings. Do not use **Save the machine state**.

## 3. Configure VirtualBox Adapter 1 — NAT

1. Open **Oracle VirtualBox**.
2. Select the CentOS VM.
3. Open **Settings → Network → Adapter 1**.
4. Configure:

```text
Enable Network Adapter: Checked
Attached to: NAT
Virtual Cable Connected: Checked
```

This adapter normally appears inside CentOS as `enp0s3` and receives an address similar to `10.0.2.15`.

## 4. Configure VirtualBox Adapter 2 — Bridged

1. Open **Settings → Network → Adapter 2**.
2. Configure:

```text
Enable Network Adapter: Checked
Attached to: Bridged Adapter
Name: The physical adapter currently used by Windows
Virtual Cable Connected: Checked
```

For this machine, the correct physical adapter was:

```text
Intel(R) Wi-Fi 6E AX211 160MHz
```

Choose the adapter that Windows is actually using:

- If Windows uses Wi-Fi, select the real Wi-Fi adapter.
- If Windows uses an Ethernet cable, select the real Ethernet adapter.
- Do not select VPN, Bluetooth, loopback, or unused virtual adapters.

Keep the default adapter type unless troubleshooting requires changing it. If DHCP traffic is being blocked, **Promiscuous Mode: Allow All** can be tested.

## 5. Confirm the Windows bridge driver

On Windows:

1. Open **Control Panel → Network and Internet → Network Connections**.
2. Right-click the active Wi-Fi or Ethernet adapter.
3. Select **Properties**.
4. Confirm that **VirtualBox NDIS6 Bridged Networking Driver** is checked.

## 6. Start CentOS and identify both interfaces

Start the VM and open **Network & Host Name** in the CentOS installer.

You should see two interfaces:

```text
enp0s3 → VirtualBox Adapter 1 → NAT
enp0s8 → VirtualBox Adapter 2 → Bridged
```

Do not identify them only by whether an IP is displayed. Match them conclusively using their MAC addresses:

- VirtualBox displays a MAC such as `080027F75B30`.
- CentOS displays the same address as `08:00:27:F7:5B:30`.

## 7. Enable both CentOS interfaces

For both `enp0s3` and `enp0s8`:

1. Select the interface.
2. Turn its switch **ON**.
3. Select **Configure → General**.
4. Enable automatic connection when available.

For `enp0s3`, VirtualBox NAT should normally assign an address automatically:

```text
IPv4 address: 10.0.2.15/24
Default route: 10.0.2.2
```

## 8. First try automatic DHCP on the bridged interface

For `enp0s8`:

1. Select **Configure → IPv4 Settings**.
2. Select:

```text
Method: Automatic (DHCP)
```

3. Save the configuration.
4. Turn `enp0s8` OFF, wait five seconds, and turn it ON again.
5. Wait approximately 20–30 seconds.

If an address such as `192.168.1.x` appears, DHCP is working and no manual address is required.

## 9. If DHCP fails, find the network details

Open Command Prompt on Windows and run:

```powershell
ipconfig
```

Locate **Wireless LAN adapter Wi-Fi** or the active Ethernet section. In this setup, Windows reported:

```text
IPv4 Address:    192.168.1.9
Subnet Mask:     255.255.255.0
Default Gateway: 192.168.1.1
```

This means the local subnet is `192.168.1.0/24`. Valid device addresses are normally within `192.168.1.1` through `192.168.1.254`, but every device must have a unique address.

## 10. Select a safe static address

Before assigning an address, verify that another device is not already using it. For example:

```powershell
ping 192.168.1.200
```

- If it replies **before** you configure CentOS, the address is already occupied; choose another address.
- If it starts replying **after** you configure CentOS, that normally confirms the VM is reachable.

For the most reliable long-term setup, inspect the router's DHCP range and either:

- Select an unused address outside the DHCP pool, or
- Create a DHCP reservation for the CentOS bridged adapter's MAC address.

This prevents the router from assigning the same address to another device.

## 11. Configure a manual IPv4 address

On the CentOS installer screen:

1. Select `enp0s8`.
2. Open **Configure → IPv4 Settings**.
3. Change the method to **Manual**.
4. Select **Add**.
5. Enter:

```text
Address:  192.168.1.200
Netmask:  255.255.255.0
Gateway:  192.168.1.1
DNS:      192.168.1.1, 8.8.8.8
```

6. Save the configuration.
7. Turn `enp0s8` OFF, wait five seconds, and turn it ON again.

CentOS should now display:

```text
IPv4 Address: 192.168.1.200/24
```

## 12. Verify the configuration after installation

Inside CentOS, show a short summary of all interfaces:

```bash
ip -br address
```

Or inspect only the bridged interface:

```bash
ip address show enp0s8
```

Expected bridged entry:

```text
inet 192.168.1.200/24
```

Check NetworkManager:

```bash
nmcli device status
```

Test the router:

```bash
ping -c 4 192.168.1.1
```

Test internet connectivity:

```bash
ping -c 4 8.8.8.8
```

Test DNS resolution:

```bash
ping -c 4 google.com
```

## 13. Verify communication from Windows

From Windows Command Prompt or PowerShell:

```powershell
ping 192.168.1.200
```

A successful reply confirms this path:

```text
Windows → local network/router → CentOS VM → Windows
```

## 14. Connect to CentOS using SSH

Install and enable the SSH server in CentOS if it is not already available:

```bash
sudo dnf install -y openssh-server
sudo systemctl enable --now sshd
sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --reload
```

From Windows:

```powershell
ssh YOUR_CENTOS_USERNAME@192.168.1.200
```

Replace `YOUR_CENTOS_USERNAME` with the user created during installation.

## 15. Common problems

### `enp0s8` says Connected but has no IP

This means the virtual cable is connected, but the router did not provide a DHCP lease. Try:

1. Confirm **Automatic (DHCP)** is selected.
2. Turn the interface OFF and ON.
3. Confirm VirtualBox is bridged to the active physical adapter.
4. Disable VPN software temporarily.
5. Try **Promiscuous Mode: Allow All**.
6. Restart Windows and the VM.
7. Use a carefully selected static address if DHCP remains unavailable.

### NAT works but Bridged mode does not

Some Wi-Fi routers, mobile hotspots, corporate networks, VPNs, or wireless drivers block or limit additional virtual devices. NAT may still work because VirtualBox shares the host's connection internally.

### Windows cannot ping CentOS

Check the CentOS firewall and interface address:

```bash
ip -br address
sudo firewall-cmd --state
```

Also verify that Windows and CentOS use the same subnet—for example, both must be in `192.168.1.x/24`.

### Duplicate IP warning or intermittent connectivity

Another device may be using the same static address. Select a different unused address or reserve the VM's address in the router.

### The network changes later

If you connect Windows to a different Wi-Fi network, the `192.168.1.200` configuration may no longer match. Run `ipconfig` again and adjust the VM address, subnet mask, gateway, and DNS to the new network.

## 16. Recommended lab configuration

For home DevOps practice, the following design is useful:

| Adapter | Mode | Main use |
|---|---|---|
| Adapter 1 / `enp0s3` | NAT | Reliable internet access |
| Adapter 2 / `enp0s8` | Bridged | Access from Windows and other LAN devices |

If Bridged mode is unreliable, use **Host-only Adapter** for Adapter 2 instead. NAT will continue providing internet, while Host-only networking provides a stable private connection between Windows and CentOS.

## 17. Add an Ubuntu VM to the same network

Ubuntu Server can show the same bridged-DHCP problem as CentOS:

```text
enp0s3 → DHCPv4 10.0.2.15/24 → NAT is working
enp0s8 → autoconfiguration failed → Bridged DHCP failed
```

Configure Ubuntu's VirtualBox adapters exactly like the CentOS VM:

```text
Adapter 1: NAT
Adapter 2: Bridged Adapter using the active physical Wi-Fi/Ethernet adapter
```

Because CentOS already uses `192.168.1.200`, Ubuntu must use a different address. Test the proposed Ubuntu address from Windows before assigning it:

```powershell
ping 192.168.1.201
```

If it is unused, open Ubuntu's installer network screen:

1. Select `enp0s8`.
2. Select **Edit IPv4**.
3. Change the IPv4 method to **Manual**.
4. Enter:

```text
Subnet:        192.168.1.0/24
Address:       192.168.1.201
Gateway:       192.168.1.1
Name servers:  192.168.1.1,8.8.8.8
Search domains: leave blank
```

5. Save the configuration.

### The complete multi-machine lab

```text
Windows: 192.168.1.9
CentOS:   192.168.1.200
Ubuntu:   192.168.1.201
Router:   192.168.1.1
```

All four addresses belong to the same `192.168.1.0/24` local network. Each machine has a unique IP, so they can communicate directly:

```text
Windows ↔ CentOS
Windows ↔ Ubuntu
CentOS  ↔ Ubuntu
All machines ↔ Router
```

The router defines the network; the IP addresses are not being taken from the Windows computer. Bridged networking makes each VM appear as a separate computer connected to the router.

Verify Ubuntu from Windows:

```powershell
ping 192.168.1.201
```

Verify CentOS from Ubuntu:

```bash
ping -c 4 192.168.1.200
```

Verify Windows from Ubuntu:

```bash
ping -c 4 192.168.1.9
```

> Windows Firewall may block incoming ping requests even when the network configuration is correct.

Never assign the same bridged IP to two running VMs. For example, CentOS and Ubuntu cannot both use `192.168.1.200`; that would create an IP-address conflict.

## Final checklist

- [ ] Adapter 1 is enabled and attached to NAT.
- [ ] Adapter 2 is enabled and attached to the active physical Wi-Fi/Ethernet adapter.
- [ ] Virtual Cable Connected is enabled on both adapters.
- [ ] VirtualBox NDIS6 Bridged Networking Driver is enabled in Windows.
- [ ] `enp0s3` is ON and has a NAT address such as `10.0.2.15`.
- [ ] `enp0s8` is ON and has a unique LAN address such as `192.168.1.200`.
- [ ] Every additional VM has a different LAN address, such as Ubuntu on `192.168.1.201`.
- [ ] Windows can ping the CentOS bridged address.
- [ ] The static address is outside the router's DHCP pool or reserved in the router.
- [ ] SSH works from Windows to CentOS.
