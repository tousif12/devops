# Vagrant Lab: Ubuntu Server + CentOS Stream

This guide creates two VirtualBox VMs automatically from one `Vagrantfile`:

```text
Ubuntu Server: 192.168.56.11
CentOS Stream:  192.168.56.12
```

Vagrant automatically creates the VMs, configures networking, enables SSH access, and installs basic tools.

## 1. What each tool does

```text
Vagrantfile → Instructions describing the VMs
Vagrant     → Reads the instructions and automates everything
VirtualBox  → Runs the actual virtual machines
Ubuntu      → First guest operating system
CentOS      → Second guest operating system
```

## 2. Final network design

Each VM gets two virtual adapters automatically:

| Adapter | Purpose |
|---|---|
| NAT | Internet access |
| Private/Host-only | Communication between Windows and the VMs |

The lab will look like this:

```text
Windows host
   |
   | VirtualBox private network: 192.168.56.0/24
   |
   |-- Ubuntu Server: 192.168.56.11
   |-- CentOS Stream: 192.168.56.12

Both VMs also use NAT for internet access.
```

This is separate from the earlier bridged network:

```text
Manual CentOS VM: 192.168.1.200
Manual Ubuntu VM: 192.168.1.201
Vagrant Ubuntu:   192.168.56.11
Vagrant CentOS:   192.168.56.12
```

Therefore, the Vagrant VMs will not conflict with the manually created VMs.

Open PowerShell:

```powershell
mkdir C:\vagrant-lab

```

## 5. Create the Vagrantfile

Create a file named exactly:

```text
Vagrantfile
```

Do not add `.txt` to its name.

Open it in VS Code:

```powershell
code Vagrantfile
```

Paste the following complete configuration:

```ruby
Vagrant.configure("2") do |config|
  # Give slow systems more time to start.
  config.vm.boot_timeout = 600

  # Disable the shared /vagrant folder to avoid Guest Additions issues.
  config.vm.synced_folder ".", "/vagrant", disabled: true

  # ------------------------------------------------------------
  # Ubuntu Server
  # ------------------------------------------------------------
  config.vm.define "ubuntu", primary: true do |ubuntu|
    ubuntu.vm.box = "ubuntu-jammy-official"
    ubuntu.vm.box_url = "https://cloud-images.ubuntu.com/jammy/current/jammy-server-cloudimg-amd64-vagrant.box"
    ubuntu.vm.hostname = "ubuntu-server"
    ubuntu.vm.network "private_network", ip: "192.168.56.11"

    ubuntu.vm.provider "virtualbox" do |vb|
      vb.name = "vagrant-ubuntu-server"
      vb.memory = 1536
      vb.cpus = 2
    end

    ubuntu.vm.provision "shell", inline: <<-SHELL
      apt-get update
      apt-get install -y curl git
      echo "Ubuntu provisioning completed"
    SHELL
  end

  # ------------------------------------------------------------
  # CentOS Stream 9
  # ------------------------------------------------------------
  config.vm.define "centos" do |centos|
    centos.vm.box = "centos-stream-9-official"
    centos.vm.box_url = "https://cloud.centos.org/centos/9-stream/x86_64/images/CentOS-Stream-Vagrant-VirtualBox-9-latest.x86_64.vagrant-virtualbox.box"
    centos.vm.hostname = "centos-server"
    centos.vm.network "private_network", ip: "192.168.56.12"

    centos.vm.provider "virtualbox" do |vb|
      vb.name = "vagrant-centos-stream-9"
      vb.memory = 1536
      vb.cpus = 2
    end

    centos.vm.provision "shell", inline: <<-SHELL
      dnf install -y curl git
      echo "CentOS provisioning completed"
    SHELL
  end
end
```

Save the file.

## 6. Validate the Vagrantfile

From `C:\vagrant-lab`, run:

```powershell
vagrant validate
```

Expected:

```text
Vagrantfile validated successfully.
```

## 7. Create both VMs

Run:

```powershell
vagrant up --provider=virtualbox
```

Vagrant will:

1. Download the Ubuntu and CentOS base images.
2. Import them into VirtualBox.
3. Create both VMs.
4. Assign CPU and memory.
5. Configure NAT and private networking.
6. Configure SSH automatically.
7. Install Git and curl.

The first run can take 10–40 minutes because it downloads approximately 1–2 GB per operating system. Later starts are much faster.

## 15. Delete and recreate the lab

Delete both VMs:

```powershell
vagrant destroy -f
```

This deletes the VMs but keeps your `Vagrantfile`.

Recreate everything:

```powershell
vagrant up --provider=virtualbox
```

This is Vagrant's biggest benefit: broken VMs can be replaced consistently from code.

## 16. Change CPU or memory

Edit these values inside each provider block:

```ruby
vb.memory = 1536
vb.cpus = 2
```

Then run:

```powershell
vagrant reload
```

Recommended starting values:

| Windows host RAM | Memory per VM | Run together? |
|---:|---:|---|
| 8 GB | 1024–1536 MB | Possibly |
| 16 GB | 1536–2048 MB | Yes |
| 32 GB | 2048–4096 MB | Easily |

## 17. Add more automatic installation commands

Ubuntu provisioning uses:

```ruby
ubuntu.vm.provision "shell", inline: <<-SHELL
  apt-get update
  apt-get install -y curl git
SHELL
```

CentOS provisioning uses:

```ruby
centos.vm.provision "shell", inline: <<-SHELL
  dnf install -y curl git
SHELL
```

You can add software such as Nginx, Docker, Java, or Ansible to these blocks. Apply new commands with:

```powershell
vagrant provision
```

## 18. Common problems

### `vagrant` is not recognized

Restart PowerShell or Windows after installing Vagrant, then check:

```powershell
vagrant --version
```

### VirtualBox provider is unavailable

Confirm VirtualBox works and run:

```powershell
VBoxManage --version
```

### IP-address conflict

Change the private addresses in the Vagrantfile:

```ruby
ubuntu.vm.network "private_network", ip: "192.168.56.21"
centos.vm.network "private_network", ip: "192.168.56.22"
```

Then run:

```powershell
vagrant reload
```

### VM starts but provisioning fails

Run provisioning again:

```powershell
vagrant provision ubuntu
vagrant provision centos
```

### SSH fails

Check status:

```powershell
vagrant status
```

Restart the affected machine:

```powershell
vagrant reload ubuntu
```

For detailed output:

```powershell
vagrant ssh-config ubuntu
```

### Not enough RAM

Stop one VM:

```powershell
vagrant halt centos
```

Or lower `vb.memory` in the Vagrantfile.

## 19. Important 2026 box note

HashiCorp is retiring the HCP Vagrant Registry service. New hosted boxes stopped being accepted on October 1, 2026, and the existing hosted deployments are scheduled to stop operating after December 31, 2026.

For that reason, this guide uses direct URLs to official Ubuntu and CentOS `.box` files instead of depending on community box catalog entries.

If an official URL changes in the future, obtain the latest VirtualBox Vagrant image from:

- Ubuntu Public Images: <https://cloud-images.ubuntu.com/>
- CentOS Cloud Images: <https://cloud.centos.org/centos/9-stream/x86_64/images/>
